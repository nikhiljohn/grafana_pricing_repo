Command Center

The daily briefing — one screen, every pillar, every managed customer
Scores

Five pillar health scores

CloudOps, FinOps, Cloud Security, DevOps and AIOps each roll up to a single score with a one-line status note — healthy, warning, or actively being worked by an agent.

Attention queue

Needs Your Attention

Live cards ranked by severity, each with a Memory line explaining why it matters — a prior occurrence, a confidence score, an evidence trail — so triage doesn't start from zero.

Org switcher

Multi-customer book

Switch between managed customers and their environments (production, staging, UAT, dev) from one dropdown. Every pillar page re-renders for whichever account is selected.

Reporting

One-click PDF reports

A branded, board-ready health report generates client-side for whichever pillar and customer is currently in view — scores, findings, and patterns as a downloadable PDF.

☁

CloudOps

Reliability, capacity, and the causal chain behind every incident

Compute & GKE monitoring

Per-instance CPU, memory, and cost, with the last incident on each resource surfaced inline — not buried in a separate dashboard.

Incident causal chains

Every incident links to what preceded it and what it caused — a Friday deploy that led to a P2, traced automatically from the Memory graph.

Serverless & pipeline health

Function invocation rates, latency, and error rates; data pipeline run history with duration and next-run scheduling.

Recurring-pattern detection

Capacity patterns — like GKE hitting memory pressure at a consistent 65% of projected load — get named and tracked across every occurrence.

$

FinOps

Cost anomalies matched to known patterns, in minutes not days

Anomaly detection with root cause

A cost spike is matched against prior spikes on the same resource class — same query shape, same root cause — with a confidence score and a suggested fix.

Optimization tracking

Applied and pending recommendations (committed-use discounts, right-sizing, lifecycle policies) with actual savings realized, not just projected.

Cost-by-pillar breakdown

Spend attributed to CloudOps, SecOps, DevOps and AIOps individually, each with its own trend line and Memory note on what changed.

Forecasting

Month-ahead cost projections that account for pending optimizations and known seasonal patterns (like pre-sale traffic ramps).

🛡

Cloud Security

Findings, IAM risk, and compliance evidence — attached automatically

Findings with Memory context

Every finding shows how many times it's been seen, the last resolution, and a confidence score for auto-fix — sourced from your own remediation history, not a generic playbook.

IAM risk scoring

Service accounts and users ranked by risk with plain-language reasoning — "Editor since creation, memory shows 8 similar cases resolved with custom roles."

Compliance frameworks

CIS Benchmark, NIST 800-53, ISO 27001, and PCI-DSS tracked as live pass/fail scores, not a point-in-time audit snapshot.

Auto-remediation with evidence

High-confidence fixes (like restricting SSH to a VPN CIDR) apply automatically and attach compliance evidence to the remediation record — no separate evidence-collection step.

⌥

DevOps

Change guardrails learned from your own incidents

Risk-scored change log

Every change — a role binding, a machine-type change, a query pattern shift — is scored Low/Medium/High with the Memory reasoning behind the score.

Orchestration requests

Provisioning requests (a new VM, a GCS bucket, an IAM role) queued for approval with estimated cost and risk, informed by how similar requests played out before.

Patch compliance

Days-behind tracking per resource with severity, plus Memory notes on why a patch was deferred (a change freeze, a compatibility test in progress).

Pre-deploy guardrails

A prior incident — like a CI bot granted Editor — becomes a standing rule that blocks the same pattern before it ships again.

✦

AIOps

Agents that act on Memory, not just alert on a threshold

Autonomous agents

Purpose-built agents (security auto-remediation, cost anomaly, predictive operations) each carry their own confidence threshold and current status — active, investigating, or idle.

Full audit trail

Every AI decision is logged with its reasoning, the Memory match that informed it, and its outcome — executed, awaiting approval, or flagged for human review.

Memory Chat

Ask plain-language questions — "what changed in the last 24h?", "what's our biggest cost risk?" — answered from the graph, with cited events and patterns.

Transparent cost

Token usage and spend broken down by feature (auto-remediation, anomaly analysis, reports) — all billed to the customer's own BYOK key, never marked up.

Memory

The graph underneath every pillar — the actual product

Timeline of entries

Every ticket becomes an entry tagged by pillar and customer, with a confidence score and a running count of how many times it's been reused.

Incident patterns

Recurring behaviors — surfaced once occurrence count and confidence both clear threshold — with occurrence counts and auto-resolution rates.

Remediation library

Proven fixes with success rates, so a new fix is only auto-executed once it has a track record, not on its first attempt.

Cross-pillar learnings

Insights that span disciplines — "IAM changes correlate with 40% of security findings within 48h" — that a single-pillar tool would never surface.

Assets & Alerts

The inventory and the interrupt queue

Asset / CMDB inventory

Every resource across GCP and AWS — VMs, Cloud SQL, Cloud Run, EC2 — with cost, region, state, and last-seen timestamp in one searchable table.

Alert feed with filters

Active, acknowledged, and resolved alerts across all pillars, each with baseline vs. current values so a spike's magnitude is immediately clear.

⚙

Platform & Security

How it's deployed, authenticated, and kept isolated

Per-customer isolation

Every customer runs on its own VM with its own Postgres, Neo4j, and Redis — no shared database, no cross-tenant query risk.

Auth: TOTP 2FA + Google SSO

Email/password with Google Authenticator-compatible 2FA, or Sign in with Google — session revocation backed by Redis, not just a stateless token.

BYOK, encrypted at rest

Anthropic, OpenAI, or Gemini keys, encrypted with pgcrypto — only the last 4 characters are ever shown in the UI, the plaintext key never leaves the LLM call path.

Auto-TLS, locked-down network

Caddy handles certificate provisioning automatically; only ports 80/443 are exposed. Postgres, Neo4j, and Redis are reachable only on the private network.
