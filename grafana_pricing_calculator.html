🎯 Grafana Prospecting & Discovery Guide

Use this before any Grafana Cloud sales call. Covers greenfield deployments and DataDog / New Relic replacement scenarios. Click each section to expand. Use the notes fields to capture answers live.

📦 Greenfield 🔄 DataDog Replacement 🔄 New Relic Migration ☁️ Cloud-Native 🏢 Enterprise

⚡ Pre-call quick checks

  • Look up customer on LinkedIn/web — team size, tech stack, cloud provider
  • Check G2 / Gartner reviews they've posted for DataDog / New Relic
  • Check their job postings — mention of Grafana, Prometheus, OpenTelemetry = strong signal
  • Check contract renewal date if they're a public company (10-K, procurement notices)
  • Look for GitHub repos using Prometheus exporters or Loki — shows existing familiarity

🔄 4 — DataDog / New Relic Replacement Deep-Dive Migration Only ▼
⚠️
Use this section only when the customer has confirmed they're evaluating migration

These questions go deeper on competitive positioning. They help you map DataDog/NR features 1:1 to Grafana equivalents and surface migration risk early.

Migration
Which DataDog / New Relic modules are active on your contract — APM, Infrastructure, Logs, Synthetics, RUM, Error Tracking, Incident Management, Security Monitoring?
Maps each module to its Grafana equivalent. Unused modules = cost savings opportunity. Active modules = migration workstreams.
APM → Tempo + Pyroscope Infra → Alloy + Mimir Logs → Loki Synthetics → Grafana Synthetics RUM → Faro Incidents → OnCall
Migration
How are you billed — per host, per GB ingested, per user, or a combination? Have you hit any cardinality limits or sampling caps?
DataDog's per-host model punishes elastic cloud infra. New Relic's per-GB model punishes high-volume log ingestion. Grafana's model is transparent usage-based — frame the comparison explicitly.
Migration
How long do you retain telemetry data today, and are you hitting storage cost issues with long-retention requirements?
DataDog retains logs for 15 days by default; longer retention is very expensive. Grafana + object storage (S3/GCS) enables cheap long-term retention — powerful differentiator.
Migration
Do your developers self-service their dashboards and alerts, or is there a central platform team that gates access?
DataDog's UI is more approachable for non-technical users; Grafana's strength is power-user flexibility and OSS extensibility. Understand who the end users are to frame the right benefit.
Migration
Are you also running a self-hosted / OSS Grafana stack (Prometheus + Grafana OSS) alongside DataDog/NR? If so, what would it take to consolidate?
Many orgs run both (DataDog for APM, Prometheus+Grafana for infra). Grafana Cloud consolidates both — strong consolidation story with immediate cost and operational savings.
Migration
What's your tolerance for a phased migration vs. a hard cutover? Is there an acceptable parallel-run period?
Grafana supports dual-shipping from OTel collectors — customers can run both stacks simultaneously. This de-risks migration and is a common objection handler vs. "too risky to switch".
🌱 5 — Greenfield / New Deployment Questions Greenfield ▼
🚀
Use this section for new observability programs or teams starting fresh

Greenfield is an opportunity to set the architecture right from day one with OpenTelemetry + Grafana Cloud. Focus on time-to-value and avoiding future lock-in.

Greenfield
Are you starting from zero or do you have some basic monitoring (CloudWatch, Azure Monitor, basic Prometheus) today?
Existing cloud-native monitoring = quick wins via Grafana data source integrations. True greenfield = focus on OTel instrumentation and getting to first dashboard fast.
Greenfield
What's driving the decision to invest in observability now — an incident, a growth milestone, a compliance requirement, or a new engineering initiative?
The trigger shapes urgency and budget justification. Incident-driven = urgent. Compliance = budget already allocated. Growth milestone = tie to engineering OKRs.
Greenfield
How many engineering / SRE / platform teams will consume the observability platform? Will it be a shared service or per-team deployment?
Shared service = centralised Grafana Cloud org with RBAC. Per-team = multiple stacks or multi-tenancy with isolated data sources. Sizing and governance model differs significantly.
Greenfield
Do you have a preference for a managed SaaS model (Grafana Cloud) vs. self-hosted (Grafana Enterprise / OSS)?
Cloud = faster time to value, no ops burden. Self-hosted = data sovereignty, existing GCP/AWS/Azure compute already paid for. Both can be positioned by Searce.

🚩 8 — Red Flags & Objection Handlers Risk & Objections ▼
Watch for
"Grafana doesn't have full-text log search like Splunk / DataDog Logs."
Response: Loki uses label-based querying (LogQL) which is faster and cheaper for structured / semi-structured logs. For compliance/audit use cases, Grafana integrates with Elastic for full-text. For most cloud-native workloads, LogQL is sufficient — and Grafana is 80% cheaper than Splunk for equivalent log volumes.
Watch for
"Our developers only know DataDog — migration effort is too high."
Response: Grafana supports DataDog-compatible API endpoints (Alloy can forward to Grafana Cloud directly). Most DataDog dashboards can be imported with the DataDog-to-Grafana migration tool. A phased migration with dual-shipping means zero downtime risk. Searce provides migration services to reduce internal effort.
Watch for
"New Relic gives us free 100GB/month data ingestion — Grafana can't match that."
Response: New Relic's free 100 GB is on their standard platform but charges $0.30/GB beyond that with limited retention. Grafana's free tier is smaller but the pricing is more transparent and predictable. For >500 GB/month, Grafana Cloud is typically significantly cheaper. Run the calculator live to compare.
Watch for
"We need AI/AIOps anomaly detection — does Grafana have that?"
Response: Grafana Machine Learning (available on Pro/Advanced) provides anomaly detection and forecasting on metrics. It's not as deep as Dynatrace Davis AI, but covers 80% of use cases. For AI-first requirements, position Grafana + Google Cloud Vertex AI / Cloud Monitoring as a complementary stack via Searce.
Watch for
"We have an existing multi-year DataDog contract we can't break."
Response: Explore if any modules are unused and can be dropped at renewal. Start a parallel Grafana Cloud POC for new services — plant the seed for migration at renewal. Early termination fees are sometimes negotiable; Grafana/Searce can sometimes help with the business case for early exit.
